## Обновление Telegram

Бот **@LogicPulseLeadsBot**, имя **LogicPulse | Заявки**.
Отдельный контейнер telegram-worker читает надёжную очередь в lp_telegram_deliveries.
Заявка и очередь фиксируются одной транзакцией. Сетевые ошибки/429/5xx повторяются
с задержкой от 30 секунд до часа (retry_after может увеличить паузу).
Постоянные ошибки 400/401/403 отмечаются failed и доступны для ручного повтора
после исправления причины. GET /api/admin/telegram показывает состояние.
При выключенных уведомлениях очередь не создаётся. Старые заявки не пересылаются.

Доставка at-least-once: при обрыве ответа Telegram или аварии после отправки
возможна повторная копия сообщения с тем же номером заявки. Дубликата заявки в БД нет.
Токен отсутствует в backend/frontend, передаётся только контейнеру отправки.
Подробности установки, проверки, выключения и отката — в docs/TELEGRAM.md.

## Архитектура

Сохранены nginx, postgres, pgadmin, registry, watchtower; добавлен backend.
`db` — сетевой alias существующего postgres, а не новый сервис или том.
Это сохраняет текущую БД и резервное копирование. Backend подключён к сетям
frontend и database. Порты PostgreSQL и backend наружу не опубликованы.

## Цены

Диапазоны в `docs/services/*.json` — стартовые оценки, не утверждённый прайс.
`prices_approved=false` скрывает цены из публичного API. Сначала сопоставьте
объём, сроки и себестоимость. Затем PUT услуги с полным телом, prices_approved=true
и price_review_note (не менее 20 символов). AI, хостинг и сторонние сервисы отдельно.

## Проверки и ограничения

Результаты: `docs/VALIDATION.md`. Прямой SSH к VPS из среды подготовки недоступен.
Работу Docker/PostgreSQL и создание услуг через Swagger на VPS проверяет владелец
после установки. Локальные проверки не подменяют проверку рабочей установки.

Заявки сохраняются в БД. Telegram включается через setup-telegram.py; email не подключён. Просмотр:
GET /api/admin/requests или pgAdmin. Страница /privacy.html описывает реализованную
обработку данных. До сбора реальных обращений владелец должен проверить сведения,
определить сроки хранения и процесс обработки запросов об удалении.

Первичная схема создаётся аддитивно (create_all). Изменения колонок будущих версий
требуют отдельной миграции. Backend использует прежнего пользователя БД;
отдельную роль с минимальными правами можно настроить следующим обновлением.
Watchtower остаётся в режиме наблюдения. Бэкап БД включает новые таблицы,
но не Registry, сертификаты или весь VPS. Подтверждённого теста восстановления нет.

## Разработка

Python 3.12: `pip install -r backend/requirements-dev.txt`.
Настройте POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, DB_HOST, ADMIN_API_KEY.
Из backend: `uvicorn app.main:app --host 127.0.0.1 --port 8000`.
Node 24, из frontend: `npm ci && npm run dev`.
Vite проксирует /api, /docs, /openapi.json на localhost:8000.
Сборка: `npm run build`; результат frontend/dist нужно скопировать в site.
Тесты: из backend `python -m pytest -q` (SQLite, не production).

## Новая установка и откат

Для текущего VPS используйте START_HERE. Для отдельного чистого сервера после
установки Docker, DNS и портов: init-env.sh, prepare-app.sh, create-user.sh,
bootstrap.sh. Собранный сайт включён в site/.

Обновление выводит путь `/root/logicpulse-before-v1.1-<timestamp>.tar.gz`.
Для отката сначала сохраните новый дамп. Восстановите из копии docker-compose.yml,
nginx, site, scripts, README.md, create-user.sh и .env в /opt/logicpulse;
проверьте `docker compose exec -T nginx nginx -t` и сделайте reload Nginx.
Новые таблицы не удаляйте: они могут содержать заявки и не мешают старому сайту.
Не используйте `docker compose down -v`: эта команда удаляет данные.
