## Изменения безопасности

Новые аккаунты получают только роль user. Администратор создаётся CLI на VPS.
Пароли хешируются scrypt; сессионные токены хранятся в БД только в виде SHA256.
Cookie Secure/HttpOnly/SameSite, CSRF для изменений и проверка Origin.
Nginx ограничивает частоту входов и записи метрик. Валидационные ошибки не
возвращают введённые пароли. Все пользовательские данные в интерфейсе выводятся
через textContent. Сервер повторно проверяет права для каждого admin endpoint.

Сервисные данные не удаляются при выключении pgAdmin/Registry. Публичных портов
8000/5432/5000/5050 нет; временный pgAdmin привязан только к loopback и профилю
maintenance. Серверный Xray и приватный Unix-сокет остаются прежними.

Метрики только по согласию, без содержимого форм и персональных идентификаторов.
90-дневное удаление требует работающего housekeeping.timer; резервные копии
управляются отдельно и могут содержать более старые данные. Это техническое
уведомление, не юридическая проверка политики обработки данных.

## Известные границы

Нет подтверждения email и самостоятельного сброса пароля. Heatmap — карта
нормированных координат, не воспроизведение сессии и не скриншот страницы.
Оценка лида — фиксированное объяснимое правило, не прогноз вероятности сделки.
Схема добавляется через create_all; существующие таблицы не перестраиваются.
Средние считаются на посещение; повторный заход — новая сессия. График метрик
рассчитан на текущий небольшой поток, не на миллионы событий в сутки.

Открытые вопросы приёмки: установка на VPS, внешний тест портов, настоящий
CRUD через таблицу и Swagger, контроль CSS/JS в браузере, 2–3 минуты активности,
проверка behavior_metrics в pgAdmin, SQL-файл на PostgreSQL, живое уведомление.
