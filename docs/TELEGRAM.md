# LogicPulse | Заявки — подключение Telegram

Действующий сайт остаётся в `/opt/logicpulse`. Услуги, заявки, .env, сертификаты,
Registry и pgAdmin сохраняются. Не запускайте bootstrap повторно и не удаляйте тома.

## 1. Windows PowerShell — загрузить архив

Скачайте LogicPulse_Server_v1.1.1.zip в «Загрузки».

```powershell
scp -i "$env:USERPROFILE\.ssh\logicpulse_root_ed25519" "$env:USERPROFILE\Downloads\LogicPulse_Server_v1.1.1.zip" root@185.125.218.116:/root/
```

## 2. Сервер Ubuntu — установить обновление

```bash
cd /root
python3 -m zipfile -e LogicPulse_Server_v1.1.1.zip .
bash /root/LogicPulse_Server_v1.1.1/scripts/upgrade-telegram.sh /opt/logicpulse
```

Скрипт делает дамп БД и `/root/logicpulse-before-telegram-*.tar.gz`, строит новый
образ, добавляет отправщик, обновляет backend и уведомление о данных.
Сайт/CSS/услуги не пересобираются; Nginx не меняется. Backend кратковременно
пересоздаётся. При ошибке остановитесь и сохраните вывод без .env и токена.

## 3. Сервер — привязать личный чат

```bash
cd /opt/logicpulse
python3 scripts/setup-telegram.py
```

1. Вставьте токен BotFather в запрос терминала. Символы НЕ отображаются; нажмите Enter.
2. Скрипт проверит, что токен принадлежит именно @LogicPulseLeadsBot.
3. Откройте https://t.me/LogicPulseLeadsBot → Start.
4. Отправьте боту в личном чате выведенную одноразовую команду `/connect_...`.
5. Вернитесь в терминал и нажмите Enter. Скрипт найдёт только личный чат с точной командой.
6. Придёт проверочное сообщение, затем контейнеры будут запущены с настройками.
7. Дождитесь строки «Telegram включён».

Токен не отправляйте в ChatGPT, не вставляйте в URL браузера, команды shell,
репозиторий и frontend. Настройки записываются в `.env` (600); резервная копия .env
также закрытая. Docker-администратор/root имеет доступ к переменным контейнера.
Не публикуйте `docker compose config` или `docker inspect`: они могут показать секреты.
Username бота публичный, токен — секретный.

Если у бота обнаружен webhook или другой получатель getUpdates, настройка
останавливается: скрипт не удаляет чужую конфигурацию. Ошибка network означает,
что VPS не может обратиться к api.telegram.org:443; пришлите только текст ошибки.

## 4. Проверка настоящей заявки

Откройте https://logicpulse.ru, выберите услугу и отправьте НОВУЮ тестовую заявку.
На сайте ожидается «Заявка отправлена!», в Telegram — «LogicPulse | Новая заявка».
Сообщение содержит номер, время МСК, услугу, имя, email, компанию и текст.
Длинный текст сокращается только в Telegram; полный сохраняется в БД.
Существующая тестовая заявка не пересылается автоматически.

```bash
cd /opt/logicpulse
docker compose ps backend telegram-worker
docker compose logs --tail=30 telegram-worker
```

В Swagger после Authorize: GET /api/admin/telegram → Execute. Для нового сообщения
ожидается counts.sent >= 1, status=sent. Это означает принятие сообщения API Telegram,
а не факт прочтения пользователем. Токен и персональные данные в этом ответе отсутствуют.

## Доставка и ошибки

- pending: ожидает отправки/повтора. Сетевые ошибки, 429 и 5xx повторяются автоматически.
- sent: Telegram принял сообщение.
- failed: постоянная ошибка. 401 — токен, 403 — блокировка бота/запрет,
  400 — неверные параметры. Исправьте причину и выполните в Swagger
  POST /api/admin/telegram/{request_id}/retry с номером нужной заявки.
- Обновить токен/привязку можно повторным запуском setup-telegram.py.
- Недоступность Telegram не отменяет сохранение заявки и успех формы.
- При аварии после отправки, но до записи результата, возможна повторная копия
  сообщения с тем же номером. Telegram sendMessage не имеет ключа идемпотентности.
- Привязка служит для уведомлений; бот не является чат-ассистентом и не отвечает
  на произвольные команды после настройки.

Очередь создаётся только для новых заявок, когда TELEGRAM_ENABLED=true. В очередь
не записан адрес получателя: смена привязки направит ещё не отправленные уведомления
в новый подтверждённый чат. Для этой версии поддерживается один личный чат.

## Выключить Telegram

В `.env` установите `TELEGRAM_ENABLED=false`, затем на сервере:

```bash
cd /opt/logicpulse
docker compose up -d --no-deps --wait backend telegram-worker
```

Сайт продолжит сохранять заявки. Существующая очередь останется до следующего включения.
Новые заявки, принятые при выключенном Telegram, автоматически в очередь не попадут.

## Откат к версии до Telegram

Не восстанавливайте старый дамп поверх рабочей БД: это удалило бы новые заявки.
Из созданного архива можно восстановить прежние backend, docker-compose.yml и .env;
сначала остановите только telegram-worker. Затем пересоберите backend и запустите его.
Таблица lp_telegram_deliveries аддитивная и может остаться — предыдущему backend
она не мешает. Полный архив содержит секреты и хранится только у владельца.
Для точных команд используйте фактическое имя резервной копии из вывода обновления.

## Источник протокола

Официальная документация: https://core.telegram.org/bots/api — getMe,
getWebhookInfo, getUpdates, sendMessage, retry_after. Реальные сетевые проверки
и доставка выполняются на VPS после ввода токена владельцем.
