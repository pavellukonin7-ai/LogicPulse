# LogicPulse 1.2 — установка и приёмка

Это продолжение работающего проекта `/opt/logicpulse`, а не новый сайт.
Существующие услуги, заявки, тома PostgreSQL, сертификаты, `.env`, резервное
копирование и серверный Xray сохраняются. Не запускайте старые upgrade-скрипты
после перехода на 1.2. Не используйте `docker compose down -v`.

## 1. Загрузка и установка

**Windows PowerShell**, если ZIP лежит в «Загрузках»:

```powershell
scp -i "$env:USERPROFILE\.ssh\logicpulse_root_ed25519" "$env:USERPROFILE\Downloads\LogicPulse_Server_v1.2.0.zip" root@185.125.218.116:/root/
```

**Терминал VPS**, приглашение `root@logicpulse`:

```bash
python3 -m zipfile -e /root/LogicPulse_Server_v1.2.0.zip /root/
bash /root/LogicPulse_Server_v1.2.0/scripts/upgrade-v1.2.sh
```

Установщик рассчитан на вашу 1.1.3 (образ приложения в ней 1.1.2). Сначала
проверяет Compose, создаёт дамп БД и архив прежних файлов, собирает frontend
и backend, проверяет Nginx с существующим сертификатом. Затем останавливает
pgAdmin/Registry, обновляет файлы и выполняет пересборку/запуск контейнеров.
При ошибке этого этапа пытается вернуть предыдущие файлы и контейнеры.
Новые таблицы при откате остаются; старые таблицы не удаляются.
Скопируйте созданные резервные копии за пределы VPS.

```bash
cd /opt/logicpulse
docker compose exec backend python -m app.manage admin
```

Введите свой email и новый пароль от 12 символов дважды. Ввод пароля скрыт.
Это отдельная учётная запись сайта: пароль pgAdmin и токен Telegram не нужны.
Команда с уже существующим email назначает роль admin, меняет пароль и завершает
предыдущие сессии этого аккаунта. Не публикуйте пароль или `.env` в чате.

Откройте `https://logicpulse.ru/account.html`, войдите и перейдите
в `https://logicpulse.ru/admin.html`.

## 2. Регистрация и Swagger

1. В приватном окне откройте главную → «Зарегистрироваться».
2. Создайте отдельный обычный тестовый аккаунт. После успешной регистрации
   происходит вход и переход на главную; «Войти» и «Зарегистрироваться» скрыты,
   появляется «Выйти». Обновите страницу — состояние должно сохраниться.
3. Обычный аккаунт не получает админ-доступ. В админ-панели ему показывается
   сообщение об отсутствии роли. После выхода кнопка регистрации возвращается.
4. Swagger в продакшене: `https://logicpulse.ru/docs`. `localhost:8000/docs`
   относится к локальной разработке; публичный порт 8000 открывать не нужно.
5. Откройте **POST /api/auth/token → Try it out**. Введите JSON с полями
   `email` и `password` своего администратора. **Execute** → 200 и `access_token`.
6. **Authorize → HTTPBearer**: вставьте только значение `access_token`, без
   кавычек и префикса Bearer. Поле X-Admin-Key для этой проверки оставьте пустым.
7. **GET /api/auth/me** → 200 и `role: admin`; **GET /api/admin/services** → 200.
8. С токеном обычного аккаунта запрос к admin должен вернуть 403; без входа,
   cookie и ключа — 401. Для чистой проверки используйте приватное окно.
9. **POST /api/auth/logout** отзывает текущий токен. Повторный защищённый запрос
   с ним должен вернуть 401. Токен действует до 12 часов, не сохраняйте его в код.

Cookie-вход использует HttpOnly/Secure/SameSite=Lax и CSRF-токен для изменений.
В браузере CSRF обрабатывается автоматически; для Swagger удобнее HTTPBearer.
X-Admin-Key оставлен для совместимости прежних скриптов. Самостоятельного
восстановления пароля по email в этой версии нет; администратор управляется CLI.

## 3. Пять услуг через визуальную таблицу

Откройте «Услуги» → «Добавить услугу +». Введите название, уникальный slug,
описание от 20 символов и внутренний диапазон цен. Оставьте «Показывать на сайте».
Пока смета не проверена, **не отмечайте** разрешение публикации цен.
Существующие услуги из прошлой версии уже будут в таблице — не дублируйте их.

| Направление | Slug | Внутренний черновик диапазона, ₽ | Пример границ работ |
|---|---|---:|---|
| Разработка сайтов и веб-сервисов | web-development | 150 000–600 000 | Дизайн, адаптивная вёрстка, формы, API; 4–10 недель |
| Разработка AI-ассистентов и чат-ботов | ai-assistants | 120 000–450 000 | Один канал, база знаний, передача оператору; 3–8 недель |
| Автоматизация бизнес-процессов | business-automation | 100 000–500 000 | Обследование и 1–3 согласованных процесса; 3–10 недель |
| Интеграция систем и API | api-integration | 80 000–350 000 | Две системы, согласованные сущности и повторы ошибок; 2–6 недель |
| Разработка внутренних бизнес-систем | internal-systems | 300 000–1 500 000 | MVP с ролями, журналом действий и отчётами; 8–20 недель |

Это примеры для заполнения, не рыночная оценка и не готовая оферта. Для публикации
цен согласуйте состав работ, исключения, часы команды, ставки, себестоимость,
резерв и сроки. Запишите основание в поле «Объём, сроки и себестоимость»
(от 20 символов). AI-токены, подписки, хостинг и сторонние сервисы — отдельно.

Для каждой новой услуги нажмите «Сохранить услугу». На главной обновите страницу:
направления должны появиться в каталоге и выпадающем списке формы.
Редактирование: измените описание одной услуги → сохраните → проверьте главную.
Удаление: создайте дополнительную услугу «Тест удаления» с уникальным slug,
удалите её кнопкой таблицы и обновите главную. Пять рабочих направлений остаются.
Удаление скрывает услугу из каталога, но сохраняет связанные заявки и историю.
Slug удалённой услуги остаётся зарезервированным.

Проверка API через Swagger с токеном администратора:

| Действие | Endpoint | Результат |
|---|---|---|
| Создать тестовую услугу | POST /api/services | 201, запишите id |
| Прочитать каталог | GET /api/services | 200, список активных услуг |
| Прочитать услугу | GET /api/services/{id} | 200 |
| Изменить услугу, полный JSON | PUT /api/services/{id} | 200 |
| Удалить тестовую услугу | DELETE /api/services/{id} | 204 |
| Прочитать удалённую услугу | GET /api/services/{id} | 404 |

В POST/PUT используйте поля примера Swagger. Несогласованные цены скрываются
в публичном API; в административной таблице они доступны администратору.

## 4. Аналитика и heatmap

1. На главной выберите **«Разрешить аналитику»**. По умолчанию сбор выключен.
2. Оставьте вкладку активной на 2–3 минуты. Перемещайте курсор, прокручивайте
   страницу, нажимайте ссылки услуг и поля формы. Не нужно отправлять несколько
   реальных заявок ради проверки кликов.
3. Подождите очередную отправку (раз в 10 секунд). Откройте админ-панель →
   **«Статистика пользователей» → «Обновить»**.
4. Проверьте карточки день/неделя/месяц. Это текущие календарные периоды по Москве,
   среднее активное время **на посещение**, а не время одного уникального человека.
   Скрытая вкладка и простой более 30 секунд не учитываются.
5. Выберите «Сегодня», правильный тип экрана и «Движение курсора» или «Клики».
   Heatmap показывает координаты по ширине и полной высоте страницы (0–100%),
   сгруппированные в ячейки. Это координатная карта, не наложение на скриншот.
   Если событий нет, панель сообщает об этом; вымышленные точки не добавляются.
6. Содержимое полей и персональные сведения в метриках не записываются.
   Метрики старше 90 дней очищает `logicpulse-housekeeping.timer`.

Проверка в pgAdmin делается временно через SSH, без публичного порта.
На **VPS**:

```bash
cd /opt/logicpulse
docker compose --profile maintenance up -d pgadmin
```

В отдельном **Windows PowerShell**, оставьте окно открытым:

```powershell
ssh -i "$env:USERPROFILE\.ssh\logicpulse_root_ed25519" -N -T -L 127.0.0.1:15050:127.0.0.1:5050 root@185.125.218.116
```

Откройте `http://localhost:15050`, войдите своим прежним аккаунтом pgAdmin.
Servers → LogicPulse PostgreSQL → Databases → ваша база → Query Tool:

```sql
SELECT id, started_at, device, active_ms / 1000.0 AS active_seconds,
       sequence, json_array_length(points) AS points_count, clicks
FROM behavior_metrics
ORDER BY started_at DESC LIMIT 20;
```

После проверки **VPS**:

```bash
docker compose stop pgadmin
bash scripts/check.sh
```

SSH-окно закройте Ctrl+C. Registry остаётся выключенным всё время.

## 5. Десять заявок и приоритеты

SQL урока не предоставлен. В `docs/seed-test-leads.sql` — эквивалентный тестовый
набор для схемы LogicPulse. После появления хотя бы одной активной услуги:

```bash
cd /opt/logicpulse
docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < docs/seed-test-leads.sql
```

Ожидается hot=4, warm=3, cold=3. Альтернатива с тем же набором через Python:
`bash scripts/seed-test-leads.sh`. Выберите один способ. Повтор не создаёт
дубликаты. Тестовые записи явно помечены; уведомления Telegram не создаются.

В панели «Заявки» включите «Показывать тестовые». Нажмите «Обновить».
Сначала идут 4 записи со 100 баллами, затем 3 с 50 и 3 с 25 (реальные заявки
могут находиться между ними). «Просмотр» показывает контакт, задачу и основания.

Правило 1.2.0: срочно +50, в течение месяца +25; бюджет ≥300 тыс. +25,
≥100 тыс. +15; компания +10; описание от 100 символов +15. Порог горячего ≥65,
тёплого ≥35; иначе холодный. Это прозрачная сортировка для менеджера,
не AI-прогноз покупки. Старые заявки без оценки отображаются «Не оценена».

После приёмки удалить только этот тестовый набор:

```bash
docker compose exec -T backend python -m app.manage remove-tests
```

Для живого сквозного теста отправьте одну новую заявку с главной и дождитесь
«Заявка отправлена!». Она появится в панели и в вашем Telegram при рабочем прокси.

## 6. Порты, сборка и журналы

По умолчанию работают nginx/backend/postgres/telegram-worker/watchtower.
Backend и postgres доступны только внутри Docker. Их закрытый TCP-порт
возвращает отказ/таймаут соединения, **не HTTP 403**. PostgreSQL не HTTP-сервис.

**Windows PowerShell** проверяет внешний доступ:

```powershell
8000,5432,5000,5050 | ForEach-Object { Test-NetConnection 185.125.218.116 -Port $_ -InformationLevel Detailed }
Test-NetConnection 185.125.218.116 -Port 443
```

Первые четыре: `TcpTestSucceeded: False`; 443: `True`.
Порт 80 открыт только для существующего ACME HTTP-01. Главная и API на нём
возвращают 403; закрыть и его можно после отдельного перехода на DNS-01.
SSH 22 сохраняется для администрирования. Не отключайте его ради «только 443».

**Терминал VPS №1**:

```bash
cd /opt/logicpulse
docker compose up --build -d
bash scripts/check.sh
docker compose exec -T nginx nginx -t
docker compose logs --tail=100 -f backend telegram-worker
```

Ctrl+C завершает просмотр журнала, не контейнеры. Реальное имя контейнера —
`logicpulse-backend-1`; `docker logs -f backend` не подходит без container_name.

**Терминал VPS №2**, при последующих изменениях frontend:

```bash
cd /opt/logicpulse/frontend
docker run --rm -v "$PWD:/work" -w /work node:24-alpine sh -c 'npm ci --no-audit --no-fund && npm run build'
cp -a dist/. ../site/
cd /opt/logicpulse
bash scripts/prepare-app.sh
```

Node на хост устанавливать не нужно. Первый установщик уже выполняет эту сборку.
В DevTools браузера → Network проверьте `/assets/*.css` и `*.js`: 200,
Content-Type для CSS — text/css. При 404 проверьте `site/assets`, монтирование
Nginx и старую вкладку/кеш. Vite выдаёт хешированные файлы; Webpack не используется.

```bash
docker compose exec -T nginx ls -l /usr/share/nginx/html/assets
curl --fail --silent --show-error https://logicpulse.ru/api/health
curl --fail --silent --show-error https://logicpulse.ru/api/services | python3 -m json.tool
python3 scripts/install-server-proxy.py --check
systemctl list-timers 'logicpulse-*'
```

Не отправляйте полный `docker compose config` или `.env` в чат: там секреты.
Для диагностики достаточно `check.sh`, статуса и журнала без токенов/паролей.

## Границы проверки

В архиве реализованы функции и проверены API на тестовой SQLite-базе.
Браузерная приёмка, SQL PostgreSQL и работа обновлённых контейнеров на вашем VPS
не считаются выполненными, пока не пройдены шаги выше. Установщик делает
проверки на сервере; не игнорируйте их ошибки. При неизвестной структуре Compose
он остановится до замены рабочего проекта.
