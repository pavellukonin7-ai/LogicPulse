# Telegram update 1.1.1 — проверка 29 сентября 2026

- 24 backend-теста прошли (12 прежних + 12 новых/параметризованных).
- Проверены: авторизация, запись заявки и очереди одной транзакцией, отсутствие
  второй записи при повторе, rollback при сбое очереди, выключенный Telegram,
  отсутствие рассылки старых заявок, 429/retry_after, повтор после новой DB-сессии,
  постоянная ошибка 403 и защищённый ручной повтор, успешная отправка без повторов.
- Проверены обработка HTTP 400/401/403/429/500, тайм-аут, отсутствие токена
  в ошибках, ограничение длины сообщения с emoji и plain text без parse_mode.
- Проверены идемпотентное изменение Compose, сохранение шести прежних сервисов,
  томов и сетей, отсутствие токена в environment backend.
- Проверены сохранение других настроек .env, права 600, резервная копия,
  отклонение повторяющихся Telegram-настроек и bash -n всех shell-скриптов.

Ограничения: тесты используют SQLite и подставной Telegram transport. Реальные
доставка Telegram, PostgreSQL SKIP LOCKED при нескольких worker и запуск Docker
в этой среде не проверялись. Они не объявлены выполненными. Один worker —
конфигурация по умолчанию. Настоящая проверка связи выполняется setup-telegram.py
на VPS с токеном владельца; затем требуется новая заявка с сайта.

Фронтенд/CSS этого обновления не меняются, кроме текста privacy.html; сборка
фронтенда из v1.1 уже проверена локально и владельцем на VPS. Вся структура
сохранена для дальнейшей работы в том же проекте.

Известное предупреждение pytest: установленный Starlette предупреждает о будущем
переходе TestClient с httpx на httpx2. Это предупреждение тестового окружения,
не ошибка работы приложения.
